# 新分支与 PR

## 触发条件

开始那些应当通过干净的分支与拉取请求工作流来交付的工作。

## 工作流

1. 确保工作树是干净的，或已被明确处理。
2. 基于最新的 main 创建一个具有描述性的分支。
3. 完成实现与测试。
4. 提交聚焦的变更并推送。
5. 创建一个简洁的 PR，包含摘要与测试说明。

## 防护准则

- 保持分支范围聚焦于一个变更集。
- 在请求审查之前附上验证说明。

## 输出

- 新分支名称
- PR 摘要与测试说明
- PR URL
