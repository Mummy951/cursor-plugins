# 修复 CI

## 触发条件

分支或 PR 的 CI 失败，需要一条快速、可迭代的路径来让检查项全部通过。

## 工作流程

1. 确定当前活动的 PR，并检查 `gh pr checks --json name,bucket,state,workflow,link`。
2. 检查失败的作业，提取第一个可采取行动的错误。可用时使用 GitHub Actions 日志；否则使用检查链接来定位失败的命令或服务。
3. 应用最小且安全的修复。
4. 推送代码，重新检查 PR 的检查项集合，并重复此过程直到全部通过。

## 防护栏

- 一次只修复一个可采取行动的失败项。
- 在进行更广泛的重构之前，优先采用最小化、低风险的更改。
- 始终以 `gh pr checks` 作为整体 PR CI 状态的真实来源。

## 输出

- 主要失败的作业及根本错误
- 按迭代顺序应用的修复
- 当前 CI 状态及下一步行动
