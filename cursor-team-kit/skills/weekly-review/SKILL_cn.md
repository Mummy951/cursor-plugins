# 每周回顾

## 触发条件

需要为状态汇报、复盘或规划提供已交付工作的每周回顾总结。

## 工作流程

1. 从仓库配置中确定当前 git 用户的邮箱。
2. 收集主分支上下文中最近 7-10 天内由自己编写的提交。
3. 排除合并提交。
4. 将有意义的更改归纳为 2-5 条简洁的要点。
5. 添加一段简短的分类说明，涵盖：
   - 可能的缺陷修复
   - 可能的技术债务工作
   - 可能的全新功能

## 约束

- 保持回顾简短，便于管理层阅读。
- 结论仅基于提交历史和差异比较。
- 如果缺少 git 邮箱，请先要求用户设置后再继续。

## 输出

- 2-5 条要点组成的每周总结
- 简短的分类段落（缺陷修复 / 技术债务 / 全新功能）
