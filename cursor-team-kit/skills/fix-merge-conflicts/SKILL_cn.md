# 解决合并冲突

## 触发条件

分支存在未解决的合并冲突，需要一条可靠的路径恢复到可构建状态。

## 工作流程

1. 通过 git status 和冲突标记检测所有冲突文件。
2. 以最小化、正确性优先的修改解决每一处冲突。
3. 在安全的情况下优先保留双方的改动。否则，选择能够编译通过并保持公共行为稳定的版本。
4. 使用包管理器工具重新生成锁文件，而不是手动编辑。
5. 运行编译、lint 和相关测试。
6. 暂存已解决的文件，并总结关键决策。

## 防护栏

- 保持改动最小且易读。
- 不要在任何文件中留下冲突标记。
- 解决冲突期间避免大范围重构。
- 解决冲突期间不要执行 push 或打标签。

## 输出

- 已解决的文件
- 重要的解决选择
- 构建/测试结果
