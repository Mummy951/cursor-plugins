# 体验优先（Experience First）

当实现的便利与用户的愉悦感冲突时，选择愉悦感。

- 每一个功能、控件和选项都必须有存在的理由
- 少交付、交付得更好（三个功能的精致体验胜过十个功能的粗糙体验）
- 在作出决定之前先做原型（设计决策在一次性 HTML 中比在生产代码中更便宜）
- 把细节做对（过渡、对齐、间距、反馈、错误状态）
- 收紧核心循环（每个功能都应服务于核心工作流，否则就让路）

用户就是消费这份工作成果的人。对 UI 而言，那就是最终用户。对库或内部 API 而言，那就是导入它的同事。接下来维护代码的工程师也是用户。以同样的方式权衡他们的体验，并从他们的角度解释影响。

基础应当服务于体验。基础性思维支配工作的*顺序*。本原则支配工作的*目标*。
