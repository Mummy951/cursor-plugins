### 编写或修改 skill

**你把控 skill 的文风。**

1. 使用 **create-skill** skill（Cursor 内置的用于编写 SKILL.md 文件的工具）。
2. 验证 skill：frontmatter 含有 `name` 和 `description`，引用的文件存在，跨 skill 链接可解析。
3. 若偏结构化则编写测试用例。主观性的则跳过。
4. 运行 **Opening a PR**。

有疑问时，删除。只保留会改变决策的散文。告诉它去做这件事，跳过原因。仅当规则在没有解释的情况下令人困惑时才解释。语气与范围相匹配。按照 **encode-lessons-in-structure** 原则 skill，指向结构化来源（类型、README、配置）。通过路径委托给其他 skill。不要重述。一个你反复遇到但尚未被记录的工作流 → 提议一个新的 skill。

**回复：** skill 的摘要、关键设计决策、验证说明。
