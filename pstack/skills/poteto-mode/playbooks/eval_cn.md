### Eval

**你负责实验设计。计划、盲化、运行、综合。**

**盲化的不可让步项：**

- 候选能看到的任何目录、文件或提示中不得出现 `eval`、`test`、`judge`、`experiment`、`rubric`、`score`、`compare`、`benchmark`、`candidate` 或 `arena`。
- 候选提示看起来像自然的用户请求。陈述目标，而非元信息。
- 不要有引出链条的线索。不要要求候选列出它们应用了哪些 skill、原则或文件。笼统地索要设计说明，并根据代码形态而非自报来给链条遵循度打分。
- 清理目录和 slug 名称。使用用户可能选择的项目形态的名称。
- 不要告诉候选还有其他候选存在。
- 评审者可以知道自己在评审，但只能看到经清理标签的输出，绝不能按模型名称。
- 比较两个变体：一名评审者在单次运行中用一个量表为两组打分，对每组来自哪里保持盲态。

**步骤：**

1. **框定。** 陈述被测的是哪个变体，以及什么行为算成功。为评审者编写评分标准（3-6 条具体标准）。对候选隐瞒它。
2. **设置清理过的环境。** 每个候选一个工作目录，变体就位。植入自然任务会拥有的任何上下文：项目骨架、候选自然会读的 skill。
3. **编写一条自然的提示。** 用户会输入的内容。不泄露正在测量什么。
4. **并行派生 N 个候选**，按 **arena** skill 的 Phase B 使用不同模型。每个在自己的清理目录中工作。每个用相同的提示。按照 Subagents 部分为每个子代理选择适合其工作的推理级别。只做分派、轮询或打包结果的代理运行在 `claude-opus-5-5-medium-fast` 上。
5. **派生一名盲态评审者**，按 **arena** skill 的 Phase C 使用不同的模型家族。评审者只看到经清理标签的输出和评分标准，绝无模型名称。
6. **从记录而非自报验证链条。** 读取每个候选在活动工作区的 `agent-transcripts/` 目录下的本地记录（系统提示点名了该路径）。不要跨 `~/.cursor/projects/*/` 做 glob。那会跨越工作区边界并读取无关项目的私人聊天。查看每个候选实际打开了哪些文件。根据它真正读取的文件以及代码形态给链条遵循度打分，绝不根据候选自己的声明。
7. **亲自从头到尾阅读每个候选输出。** 与评审者的裁决比较。不一致意味着某个模型有偏见或评分标准含糊。做综合。

**回复：** 被测变体、评分标准、每个候选的说明、评审者的裁决、你的综合，以及是否推广该变体的建议。
