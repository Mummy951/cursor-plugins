### 自主运行

**你负责退出条件。定义"完成"，然后不停歇地朝它推进。**

1. 在第一次迭代之前，将退出条件表述为一个可检查的谓词（测试通过、复现问题已修复、N 个 PR 全部合并、像素差为零）。
2. 使用 Cursor 的 `/loop` 命令选择唤醒机制（内置命令，不是 pstack skill）。要监视的事件（CI、一次合并、一个 ref 前进）配一个 watcher 子代理，在该事件发生时唤醒你，并以长时间间隔的基于时间的 heartbeat 作为后备。没有事件时则使用固定间隔的 heartbeat，间隔大小取决于结果值得重新检查的时机。按照 Subagents 部分为每个子代理选择适合其工作的推理级别。
3. 每次迭代做出证据能证明的最小改动，根据谓词验证它，若有推进则提交，丢弃没有帮助的改动。"可能有帮助"的双保险措施应回滚，而不是留着碰运气。
   通过 **sequence-verifiable-units** 原则 skill 来安排工作顺序，在下一个单元之前验证每个单元，而不是在最后批量检查。
4. 运行中期的发现若支持目标，就归你处理。通过 poteto-mode 亲自处理损坏的 skill、相关的 bug、不稳定的验证器、审查噪音、工具故障、孤立的后续事项和可修复的漂移。将带外修复放进它们自己的 PR。不要把可逆的工作搁置给人类或使用 `AskQuestion`。只上报不可逆的操作、实验无法解决的真正的产品或偏好决策，或者真正的死胡同。保持谓词作为主要驱动力，每次旁支修复后回到它。
5. 通过 **show-me-your-work** skill 在每次迭代做检查点，用一行记录改动了什么以及谓词是否推进。
6. 当谓词满足时停止。平台期不是停止，所以继续前进并调整方法以突破它。上报真正的死胡同而不是空转，永远不要放宽谓词来宣布胜利。

**回复：** 退出条件、运行的迭代次数、落地了什么、丢弃了什么、最终的谓词状态。
