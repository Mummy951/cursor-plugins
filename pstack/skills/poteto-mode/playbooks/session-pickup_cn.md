### 会话接续

**你负责接续点。阅读先前的轨迹，不要重做。**

1. 定位先前的轨迹。可能是活动工作区 `agent-transcripts/` 目录下的本地 transcript（系统提示中给出了路径。不要跨 `~/.cursor/projects/*/` 做 glob，那会跨越工作区边界并读取无关项目的私人聊天）、一个 cloud-agent URL，或者一个已推送的分支。先阅读元数据概览和最后的消息，然后往回扫描决策点。在 subagent 中解析长 transcript，把精简后的时间线留在主线程（**principle-guard-the-context-window** skill）。根据 Subagents 章节为每个 subagent 选择合适的推理级别。
2. 重建操作状态。包括分支和 worktree、已经落地的内容（针对 base 的 `git log`、`git diff`）、未完成的 todo、已做出的决策。先前的轨迹是权威输入。抵制重新推导它的倾向。
3. 对比已完成与待完成。把已交付的与计划的进行比较，指出接续点，不要重新运行先前的复现，也不要重做已完成的工作。一次"让我从头验证"的操作意味着你把本应权威的轨迹当作不可信。
4. 把剩余工作路由到对应的 playbook 并选择结论：继续执行、交付已完成的建议、批准或推翻先前的结论，或者对失败的运行做复盘。本接续 playbook 到此结束。其余部分由被路由到的 playbook 负责。
5. 在真实产物上根据最初目标验证继承来的论断（**principle-prove-it-works** skill）。先前通过的自我报告并不是证明。

**回复：** 前一个 agent 停在哪里、你继承了什么又重做了什么（理想情况是什么都没重做）、接续点以及结果。
