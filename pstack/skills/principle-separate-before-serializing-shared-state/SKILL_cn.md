# 串行化共享状态之前先做分离

当并发参与者可能写入同一个文件、分支、键或对象时，先问一问它们是需要一个共享对象，还是在发布各自独立的事实。默认做法是给每个参与者分配自己的文件、键、分支或状态目录，只在读取该状态的地方进行合并。两个工作者各自把字段写入同一个 `state.json`，依然是共享可变状态。

只有当某个共享写入目标是真正的不变量时，才在结构上对访问做串行化（锁文件、单一写入方、顺序阶段、比较并交换 compare-and-swap）。指令说明并不等于并发控制，而"我们需要一把锁"是一种应当优先核查的坏味道。
