# 打造杠杆（Build the Lever）

当工作并非平凡时，构建能完成它的工具（codemod、脚本、生成器，或可重新运行的检查），而不是手工去做。门槛是「是否平凡」，而不是「是否重复」。只有在少数几个显而易见的编辑时才跳过工具。

- 先手工完成第一个单元，然后构建工具，并在那个单元上重新运行以证明它有效。让它可安全地重复运行。
- 确定性的工具胜过扇出（fan-out）。当你确实需要扇出时，把配方、验证契约和围栏写成一个 delegate 会阅读且无法编辑的 skill。
- 应用这条原则会产出一个文件。diff 里没有脚本、codemod、生成器或 delegate skill，就说明你没有应用它。当工作的生命周期超过本次会话时，把它提交。
- 构建能做或能证明这项工作的最小脚本，永远不要构建一个框架。
