# 以结果为导向的执行

以预期的、可验证的最终状态为目标进行优化，而不是维持平滑的中间状态。

**原因：** 让每一个中间步骤都保持完全稳定，往往会产生临时兼容性代码，而这些代码会演变成长期的技术债务。应收敛到目标架构，并在明确的验证边界处证明其正确性。

**核心规则：**
- 最终状态的完整性优先于过渡阶段的稳定性
- 当中间环节的破坏是有计划的、范围可控的且可逆的，这种破坏是可以接受的

**护栏：**
- 将其用于具有明确阶段边界的计划内重写和迁移
- 声明哪些地方可以接受临时性的破坏
- 在迁移过程中，对正在积极修改的区域保留高信号的检查
- 在计划完成时要求完成完整的静态和运行时验证
