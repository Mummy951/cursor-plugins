# 创建一个形式化验证 skill

测试检查的是有人想到要写的用例。形式化验证检查的是在给定范围内的每一种情况：模型中步骤的每一种顺序、某个界内的每一个输入，或每一个输入。本 skill 找出代码库中最需要这一点的部分，验证其中一个属性，并留下一个项目本地的 skill，让下一个 agent 能够对照该属性检查改动。写这个 skill 时要设想一个冷启动阅读它、正处于改动中途、且从未见过你工作的 agent。用户必须能够信任结果并据此行动，而无需学习验证语言。

## 从代码中选择目标

从代码库中寻找答案，只询问你无法观察到的内容。如果用户指定了某个区域或某个 bug，就从那里开始。

一个好的目标是代码所作出的承诺——一旦被破坏就会伤害用户，而测试很少触及破坏它的那种情况。选择代码库中最符合这一条件的、最有力的目标，而不是最容易验证的那个。

## 让问题来选择工具

选择能以最低成本回答问题的工具：模型检查器、证明助手、基于 SMT 的验证器，或其他工具。事件是否可能以错误的顺序发生，通常适合用模型检查器对设计的一个小模型进行验证，而 TLA+ 在任意语言中都是这方面的默认选择。代码本身是否对每一个输入都表现正常（如内存安全、溢出或数据结构不变量），通常适合使用直接跑在代码上的验证器。如果没有能用于该语言的验证器，请如实说明，并用生成的输入测试真实代码，而不是手工建立的函数模型。对于必须在每一种规模下都成立、有界不足以保证的属性，可能需要证明。优先选择该代码库开发者能够安装并运行的工具，并告诉用户你选择它的理由。

## 什么样的验证是好的

- **忠实于代码。** 模型或证明的每一部分都指向审查者能够打开的代码。验证视为不可分割的那一步，在代码中也是不可分割的一步。名称来自本代码库。
- **能够失败。** 一个你从未见过其失败的检查证明不了任何事。展示每个属性在它所守护代码的一个被破坏的变体上失败，例如移除某个检查或重排某个步骤。
- **发现保持为发现。** 当当前代码破坏了该属性时，用代码中的术语和反例来报告它。不要为了让检查通过而削弱属性或模型，也不要在产品代码未经用户要求时修改它。
- **对范围诚实。** 说明验证了什么、在哪些界和假设下、以及遗漏了什么。一次通过覆盖的是模型或该界，而不是整个系统。
- **无需工具也能读懂。** 用一句朴素的话分别陈述属性和危害。用代码中的措辞，以简短的步骤序列描述反例。
- **重跑成本低。** 一条命令、一个可复现的工具版本，以及足够短的运行时间，让下一个 agent 愿意在每一次相关改动后都运行它。
- **与代码保持同步。** 记录每项检查覆盖哪些文件和函数，以及你上次确认该验证与它们相符时的提交。当所覆盖的代码在该提交之后发生变化时，下一个 agent 就能看出该验证需要重新审视。

## 生成验证 skill

编写一个项目本地的 skill，其 frontmatter 要指明该区域并说明何时使用它。没有 frontmatter，这个 skill 永远不会被注册。仅凭这个 skill，下一个 agent 就必须能够判断某次改动是否触及被验证的代码、运行检查、区分真正的 bug 与建模错误，并在改动是有意为之时更新验证。把覆盖记录和同步提交放进 skill，并告诉下一个 agent：只有在确认验证与新提交处的代码相符之后，才将同步提交向前推进。使用本代码库真实的命令、路径和术语，不要留下任何占位符。

如果检查是 TLA+ 模型，告诉下一个 agent 用 pstack 的 [`/statechart`](../statechart/SKILL.md) skill 读取每一个结果。它会用朴素的语言把检查器发现的每一处不变量违反展示为其最短路径。当检查通过时，`/statechart` 会绘制一张系统如何在状态之间迁移的图。按名称引用 `/statechart`。它的命令、选项和文件路径在不同版本和机器之间会变化，因此不要把其中任何一个复制进生成的 skill 或其脚本中。

## 在交付前证明它

像下一个 agent 那样，按照生成的 skill 执行一次，在一个会破坏真实代码中该属性的临时改动上进行。它必须捕获到这次破坏。然后丢弃临时改动，确认检查回到了初始状态：通过，或仅在你将要报告的发现上失败。一个从未运行过的验证 skill 只是草稿。如果该 skill 漏掉了破坏，或某一步没有运行，请修复 skill 或验证，而不是修复临时改动。

## 交付

告诉用户你验证了什么、使用了哪个工具及原因、界是什么、检查用朴素的语言发现了什么、如何运行它、以及它不覆盖什么。只有当你发现了一个相近的目标时，才建议第二个目标。引导用户使用 `/maintain-formal-verification-skill`，以便在没有重新检查的改动之后让验证重新与代码保持一致。
