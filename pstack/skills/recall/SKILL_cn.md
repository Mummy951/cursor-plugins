# 回忆（Recall）

**在开始或恢复工作之前，你重建用户近期的工作上下文，并交回一份紧凑的摘要，说明现在进展到哪一步以及下一步该做什么。**

保持紧凑、切题。只读取范围内会话所需的内容，然后停止。

你的上下文存在于两份记录中。你自己的聊天历史保存着你所做的事情和所做的决定。共享记录保存着同一份代码周围发生的、以其他名义发生的一切：用户不断报告的症状、已发布又被回滚的修复、仍在生产环境触发的错误。第二份记录存在于源代码控制、问题跟踪器、聊天和问题频道、长篇文档以及错误跟踪中。一个有着长长的 bug 尾巴的功能，其大部分故事都留在那里，所以不要仅凭你的会话记录来重建它。

会话记录位于 `~/.cursor/projects/<slug>/agent-transcripts/<uuid>/<uuid>.jsonl`，其中 `<slug>` 是去掉前导斜杠并将每个 "/" 替换为 "-" 后的工作区路径（因此 `/Users/you/proj` 变为 `Users-you-proj`）。每一行是一条聊天消息。

1. 先分类，再路由。要恢复某一次具体的过往聊天，应使用 `session-pickup` playbook，而不是本 skill。把习惯变成持久化的 skill 是 `automate-me`。对你的工作做人类可读的总结是另一项任务。Recall 是在你行动之前跨近期聊天加载工作上下文。如果用户已经给了你一份完整的状态摘要（路径、分支、改动），就直接使用它，跳过挖掘。
2. 搜索前锁定范围。固定时间窗口（"近期"是一个真实的范围，默认最近 7 天）、如果指定了主题则固定主题、以及工作区（默认为当前工作区。绝不在未被要求的情况下读取其他项目的会话记录）。把范围复述出来。绝不悄悄地把"全部"变成"最近 N 条"。
3. 在你的聊天历史中并行展开。在一个快速、廉价的模型上生成并行子代理，每个负责语料库的一个切片。告诉每个子代理按真实修改时间（`ls -t`）排序候选对象，绝不要按 UUID 名称排序；先按主题 grep，然后只读取匹配的聊天，且只读其中的相关区域；跳过当前聊天以及明显的噪音（子代理、评测和测试聊天）。每个子代理返回相同的 schema，每条聊天一个块：主题、用户的目标、决定、未完结的线索、挣扎和纠正，以及产物（PR、工单、分支），每条都引用聊天 UUID。对于一两场聊天，跳过并行展开，直接搜索。原始会话记录留在子代理中。主线程只得到它们的发现。根据 **poteto-mode** skill 的 Subagents 章节，为每个子代理按任务选择合适的推理级别。
4. 只要主题点名了某个功能、文件、子系统、领域或 bug，就要清扫共享记录。这是默认行为，不是需要判断的选择，而且"我在 X 上的工作"也不例外。为每个来源生成一个调查子代理，使用 agent 模式，因为 readonly 会剥离 MCP 访问权限，并询问每个子代理"当前状态是什么，尝试过什么但没有奏效，用户还在报告什么"。让它们与聊天历史挖掘并行运行。空结果也是发现。跳过不可用的 MCP 并说明这一点。把返回的内容整合进简报。仅对没有点名目标的纯活动类回忆跳过此步骤（"我这周做了什么"），此时你自己的历史和实时状态就是全部答案。
5. 对照实时状态核验。拿挖掘和清扫中发现的 PR、分支和工单，用 `git` 和 `gh` 检查它们。当答案取决于某个 agent 实际做了什么（它运行的工具、读取的文件、遇到的错误）时，读取完整的会话记录，而不只是裁剪过的本地副本。
6. 按照下面的契约写简报。按线索分组。紧扣点名的主题。

## 输出契约

先给出摘要胶囊，然后是线索状态，接着是问题，最后是下一步行动。更详细的内容放在下面或直接删掉。

- **胶囊（Capsule）。** 最多 5 条要点。说明这项工作是什么以及它整体的进展状态。
- **线索（Threads）。** 每条一行，且恰好以一个状态标签开头：`[merged #N]`、`[open PR #N]`、`[in flight <branch>]`、`[verified, uncommitted]`、`[reverted #N]` 或 `[planned, not started]`。没有标签的线索尚未完成，所以要给它打标签。
- **问题（Problems）。** 最多 5 条，写反复出现的问题。包括用户不断报告的症状，以及任何已发布又被回滚的修复，让下一次尝试从上一次失败的地方开始。
- **下一步行动（Next move）。** 单一最有用的下一步行动，要具体。

相邻的功能或工单除非阻塞了本项，否则不要纳入。当胶囊和线索行超过一屏时，先删细节，再删线索。通过 **unslop** skill 撰写简报，按 UUID 引用聊天发现、按来源（PR #、工单 ID、聊天永久链接、错误跟踪议题）引用共享记录发现，并在任何公开输出前清理隐私内容。

**回复：** 按上述契约给出简报。
