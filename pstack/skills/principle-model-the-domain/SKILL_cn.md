# 为领域建模

把领域编码到数据结构中，而不是把它散落在各种条件判断里。正确的结构让无效状态无法表示，并消除分支。

优先用状态机代替散落的布尔值或阶段检查，用带类型的模型代替松散的参数，用 map、注册表或可辨识联合（discriminated union）代替跨越文件的分支，用 reducer 代替临时拼凑的修改，并在访问模式需要时使用索引、队列或规范化集合。

不要强求。当形态清晰、局部且不太可能增长时，保留平淡无奇的代码；对于只增加间接性、却没有消除分支或无效状态的抽象，要保持怀疑。

你跳过这一步的迹象：某个功能让 if/else 链又多了一个分支，或者出现了必须与第一个保持同步的第二个布尔值。
