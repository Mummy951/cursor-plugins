# 测试行为，而非实现

测试是一条关于代码使用者能通过其接口观察到什么的声明：返回值、错误、他们能读回的状态，以及对外部系统产生的影响。私有辅助函数、内部调用顺序和中间数据都属于实现。

用两种假想的修改来评判每一个测试：

- **破坏行为**（一个错误的值、一次被跳过或重复执行的效果）。如果测试仍然通过，那它什么也证明不了。常见原因包括断言过于宽松、期望值由被测代码自身计算得出，以及针对测试自己构造的数据做断言。
- **改变内部实现**而保持所有可观察结果不变。如果测试失败了，说明它被钉死在了实现上。

保留能捕获第一种修改、且能承受第二种修改的测试。其余的重写或删除。用一个具体的输入通过代码的公共接口来驱动代码，并从需求中推导出期望值。外部服务接收到的内容是行为，而对内部辅助函数的调用则不是。把"这永远不会发生"与一个确实会发生的用例配对。断言调用者会据此分支的错误类型，而不是错误消息。
