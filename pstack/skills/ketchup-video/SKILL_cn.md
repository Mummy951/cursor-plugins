# Ketchup 视频

遵循 [`/ketchup`](../ketchup/SKILL.md)，但用一段带字幕的短视频展示发生的事情，而不是它的摘要和视觉呈现。其时间窗口从用户在 `/ketchup-video` 之前写的最后一条消息开始，而不是在更早的任何 `/ketchup` 之前。在仓库之外编写和渲染视频是其只读规则的唯一例外。回复内容是 ketchup 的开场句、嵌入的视频、一行指出你自己还能完成的剩余工作，以及待办事项。当视频展示某个调用（call）的选项时，按视频给出的名称来称呼每个选项。如果渲染失败，用一行说明，并且只给出调用。

## 幻灯片

使用工作产生的截图、录屏、diff 和数据，而不是聊天中关于它们的文字描述。在你绘制之前，先写出用户应该带走的那句话，以及每张幻灯片一行的内容。删掉每一张不改变用户认知的幻灯片。最多使用 10 张幻灯片，越少越好。这两条笔记都不要放进回复里。

每张幻灯片只讲一个要点。在一张图上构建幻灯片，并在各张之间改变它，而不是切换到一张不相关的图。一种颜色或形状在每张幻灯片上都表示相同的含义。用图展示工作，例如系统如何运作、带有每个 PR 状态的 PR 栈、修复前后的对比，或并排的选项。用箭头、高亮和动画指出变化之处。幻灯片绝不能是项目符号列表、状态列表、表格，或没有任何连接关系的方框。

把文字减到最少。把每个标签放在它所命名的东西上，用人会说的平实语言，而不是像 "Tests: pass" 这样的标签。绝不要给图片所展示的内容加文字说明，也绝不要把一个事实说两遍，无论是跨幻灯片还是在下面的文字里。

展示用户要求的每件事的结果，以及它是已完成、仍在运行、失败还是未检查。绝不要把仍在等待用户的东西显示为已完成。展示途中发现并修复的任何 bug。如果某个可见的更改没有截图，就在其幻灯片上说明，并说出屏幕上改变了什么。只根据你掌握的事实绘制。绝不要编造数字，也绝不要绘制你没有捕获过的屏幕。

## 字幕

给每张幻灯片一行简短的字幕，大约十个词，用你会告诉用户的方式说出它的要点，并且只根据该幻灯片所展示的内容。说出图片的含义，而不是读出它的标签。把字幕放在幻灯片下方的一条带状区域里，每张幻灯片的这条区域高度相同，并且除字幕外保持空白，这样它就永远不会覆盖幻灯片。把它设置得小一些，但在视频以聊天尺寸播放时要清晰可读。

## 渲染

渲染一段无声的横向视频，例如 mp4，幻灯片之间有过渡动画。每一帧就是幻灯片本身，从边缘到边缘，位于其字幕带之上。用幻灯片制作这些帧，绝不要通过录屏，并且把每条字幕烧录到其幻灯片的帧里，使其在幻灯片的整个停留期间都留在屏幕上。停留时间（hold）是指一张幻灯片完全显示在屏幕上的时间，不包括进入或离开它的动画。每张幻灯片停留的时间要足够读出它新增的文字，每三个词至少一秒。一张幻灯片新增的内容包括它的字幕以及之前幻灯片上没有出现过的每个词，包括它改变的一个标签。第一张幻灯片新增它的全部文字。截图内部的文字不计入。

在嵌入视频之前，检查渲染出来的文件。以聊天尺寸查看每张幻灯片的一帧，检查其字幕是否清晰可读且没有遮挡任何内容。通过将文件的帧与幻灯片匹配来测量每个停留时间，而不要用静帧检测器，因为后者会把淡入淡出的微弱末端计为静帧。把每张幻灯片新增的词数与其测得的停留时间对照。修复你在该时间内无法读出的任何幻灯片，重新渲染，并再次检查。
