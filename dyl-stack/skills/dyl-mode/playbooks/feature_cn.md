### 功能（Dylan 覆盖层）

先阅读共享的 playbook：pstack `poteto-mode/playbooks/feature.md`。

然后应用这些关卡（gate）。发生冲突时以它们为准。

1. 仅涉及 UI 变更：编辑前先阅读仓库的 UI 或样式指南。否则跳过。
2. 复用 UI、数据和 token 的现有事实来源（source of truth）。不要建立并行的注册表或一次性的外壳。
3. 受开关（flag）控制的工作：关闭开关的路径保持不变。共享库的修改保持增量式且默认值无副作用；尽可能优先采用界面局部化的方式。
4. UI 验证是通过 `control-ui` 在正在运行的应用程序上进行实时验证，而不仅仅是编译通过。
5. 优先使用 CSS/GPU 驱动的动画。舍弃无法做到流畅的动画，而不要交付卡顿的效果。
6. 如果在构建过程中出现问题，在修补之前先触发**根因，而非表象**关卡。
