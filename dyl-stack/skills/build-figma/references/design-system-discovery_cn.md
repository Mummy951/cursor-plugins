# 设计系统探查

在映射任何一个节点之前，先弄清仓库中已经有什么。把每个答案都记录到 `intake.md` 中。本步骤存在的意义，就是避免那种基于对组件库的猜测而做出的映射——那正是一种失败。

## 按顺序查找

1. **仓库指引。** 查阅 `AGENTS.md`、`.cursor/rules/`、`.cursor/skills/` 和 `CONTRIBUTING.md`，寻找任何关于 UI、样式、设计令牌或组件的内容。仓库本地的设计系统、样式或基础组件（primitives）skill 的优先级高于下面所有内容。完整阅读并遵循它。
2. **目标界面（surface）。** Figma 画框属于哪个应用或包。依据需求和 Figma 文件名来判断。如果仓库中有多个采用不同样式系统的 UI 界面，请指明你选择了哪一个以及原因。只有当两个界面同样合理、且选错意味着返工时，才去询问。
3. **组件库。** 该界面从中导入基础组件（按钮、文本、对话框、图标、输入框）的共享包或目录。记录其导入路径，以及它的 stories、gallery 或示例所在的位置。
4. **令牌（Tokens）。** 颜色、间距、圆角和字体比例在哪里定义，以及组件如何消费它们（CSS 变量、主题对象、工具类配置）。
5. **样式系统。** 该界面实际使用什么：CSS modules、CSS-in-JS 库、工具类、纯 CSS。检查是否有禁用某些替代方案的 lint 规则。与目标目录中的邻近文件保持一致。
6. **图标与品牌资产。** 图标集及其命名方式，以及 logo 和品牌图片所在的位置。使用前核实每个图标名称确实存在。
7. **运行中的界面。** 如何运行并捕获目标 UI（开发服务器命令、story、gallery 页面、桌面构建）。这是视觉评判中的处理侧（treatment side）。

## 在 `intake.md` 中输出

一个简短的表格：界面、代码路径、组件库路径、令牌来源、样式系统、图标来源，以及驱动其运行的命令。每一行都要注明你从中读取信息的文件。
