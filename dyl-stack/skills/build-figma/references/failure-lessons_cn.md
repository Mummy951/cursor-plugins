# 失败教训

过去的 Figma → UI 构建中暴露过哪些问题，以及每个问题催生了哪一道关卡。样式与 token 规则位于仓库自身的指南中，可在设计系统发现（design-system discovery）阶段找到。本文件只记录这些关卡为何存在。

## 出了哪些问题

1. 先交付了功能可用的 UI；只有在人类提出反对之后，才做出忠实于 Figma 的视觉。→ 关卡 1 会阻止编码，直到有了需求接收（intake）材料。
2. 手工绘制品牌标志，而不是从 Figma 导出或使用仓库中已有的资源。→ 硬性禁令 2。
3. 选用了一个看起来相近但结构不同的列表或对话框 primitive（带分隔行的凹陷卡片并不是普通列表）。→ 硬性禁令 3，node → primitive 映射表。
4. 在某个 primitive 的尺寸 token 与 Figma 的 px 不一致时，仍然信任了它。→ 度量表，硬性禁令 4。
5. 样式能编译却从未输出，或是样式系统无法处理的动态样式。→ 关卡 3，匹配相邻元素并执行 lint。
6. 猜测图标名称；在确定品牌图片尺寸之前先将其缩小，压垮了它的细节。→ 评分标准第 2、5、6 行。
7. 拿浅色主题的实现去对照深色主题的画框来评判。→ 评分标准第 0 行。
