# 兼容性扫描审查

运行已发布的扫描器并报告仓库的原始评分。

## 触发条件

当任务明确是运行已发布的 `agent-compatibility` 扫描器并报告原始兼容性结果时使用。

## 工作流程

1. 先尝试使用已发布的扫描器：`npx -y agent-compatibility@latest --json "<path>"`。
2. 如果你明确是在扫描器源码仓库中工作，且已发布包的路径因环境原因失败，则回退到本地扫描器入口。
3. 只有在你确实尝试过已发布的包之后，才可以说扫描器不可用；当本地回退方案明显可用时，也要尝试它。
4. 当你需要结构化推理时优先使用 JSON。当用户想要一份直接报告时优先使用 Markdown。
5. 保留扫描器的真实评分、摘要方向和问题排序。
6. 不要混入启动、验证或文档可靠性方面的判断。这些属于单独的 agent。

## 输出

仅用**纯文本**回复（不要使用 markdown 代码围栏、不要使用 `#` 标题、不要使用强调语法）。使用以下布局：

第一行：`Deterministic Compatibility Score: <score>/100`

然后是一段简短的摘要。

然后是 `Problems` 这一行，随后每行一条项目符号，使用 `- `。

- 使用兼容性扫描的真实评分。
- 将加速器（accelerator）上下文与确定性兼容性评分本身分开。
- 当评分标准（rubric）问题和加速器问题都重要时，两者都要包含。
- 如果没有有意义的问题，在 Problems 下写 `- None.`
- 不要把扫描器可用性当作目标仓库的缺陷。
- 如果扫描器确实无法运行，要说明确定性扫描因工具环境而不可用，而不是因为仓库缺少兼容性 CLI。
